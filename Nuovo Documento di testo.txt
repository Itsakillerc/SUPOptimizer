Sei un senior software architect, Windows systems engineer, UX/UI designer e full-stack developer specializzato nella realizzazione di utility Windows native, system optimizer, debloater e amministrazione del sistema.

Devi progettare e sviluppare da zero un'applicazione Windows portable chiamata provvisoriamente **NEXUS Optimizer**.

L'obiettivo è creare un'applicazione estremamente completa e moderna per la manutenzione, ottimizzazione, configurazione, debloat e gestione di Windows, con interfaccia web locale, ma distribuita come **singolo eseguibile portable .exe**, senza necessità di installazione, server remoto, database esterni o dipendenze da installare manualmente.

L'applicazione dovrà essere realmente utilizzabile e testabile da me successivamente all'interno di una macchina virtuale Windows.

## 1. REQUISITI GENERALI

L'applicazione deve:

* essere progettata principalmente per Windows 10 e Windows 11;
* essere distribuita come singolo `.exe` portable;
* non richiedere un installer;
* non richiedere Node.js, Python, Java, .NET Runtime, browser particolari o altre dipendenze esterne già installate dall'utente;
* utilizzare esclusivamente componenti/runtime che possano essere incorporati nel progetto e nel build finale;
* funzionare completamente in locale;
* non dipendere da servizi cloud per le funzioni principali;
* non inviare dati personali o telemetria a server esterni;
* essere compatibile con una modalità non amministratore quando possibile;
* richiedere elevazione amministrativa solo per le operazioni che ne hanno realmente bisogno;
* gestire correttamente UAC;
* essere robusta in caso di errore;
* non applicare automaticamente modifiche pericolose;
* fornire sempre informazioni chiare prima di eseguire tweak potenzialmente invasivi.

Preferenza architetturale:

**Windows native host + web UI locale embedded**, con una tecnologia che permetta di produrre un singolo `.exe` portable e con footprint ragionevole.

Valuta autonomamente quale stack sia più appropriato tra:

* Rust + WebView2 / alternativa embedded;
* C#/.NET self-contained + WebView2;
* Go + embedded webview;
* altra soluzione equivalente.

La scelta deve essere motivata in base a:

* portabilità;
* dimensioni;
* sicurezza;
* accesso alle API Windows;
* gestione tray;
* gestione privilegi;
* possibilità di distribuire un singolo executable;
* facilità di build;
* assenza di dipendenze esterne.

Non voglio un semplice prototipo grafico: voglio una base architetturale realmente estendibile e funzionale.

# 2. COMPORTAMENTO DELL'APPLICAZIONE

Quando lancio:

`NexusOptimizer.exe`

l'applicazione deve:

1. avviarsi;
2. rimanere in background;
3. comparire esclusivamente nella **system tray di Windows**;
4. utilizzare una propria icona;
5. non occupare inutilmente la taskbar;
6. avviare il motore locale necessario alla web UI;
7. mantenere l'applicazione attiva anche quando la finestra web viene chiusa.

La finestra principale deve essere mostrata solo quando richiesto.

Nel tray deve essere presente un menu contestuale con almeno:

* Apri;
* Dashboard;
* Quick Optimize;
* Scansione sistema;
* Impostazioni;
* Informazioni;
* Riavvia applicazione;
* Chiudi.

Il click sull'icona del tray deve aprire automaticamente la UI principale.

Il click destro deve aprire il menu contestuale.

La voce:

**Chiudi**

deve terminare completamente l'applicazione.

Se la finestra web viene chiusa tramite il normale pulsante X, NON deve necessariamente terminare il processo: deve semplicemente nascondere la UI e lasciare il programma nel tray.

Implementare un comportamento coerente tra:

* apertura;
* minimizzazione;
* chiusura finestra;
* chiusura applicazione;
* riapertura dal tray.

* System metric card;

* Error state.

# 41. PERFORMANCE

L'applicazione deve consumare poche risorse quando rimane nel tray.

Quando è inattiva:

* CPU prossima allo zero;
* RAM contenuta;
* nessun polling aggressivo.

Usare event-driven architecture dove possibile.

Monitoraggio hardware aggiornato con intervalli ragionevoli.

---

# 44. REGOLE IMPORTANTI SUI TWEAK

Non inserire "fake optimization".

Non utilizzare tweak basati esclusivamente su miti del tipo:

* "svuota RAM = PC più veloce";
* "disabilita tutti i servizi";
* "imposta priorità realtime per tutto";
* "modifica timer magici";
* "disabilita componenti Windows casuali".

Ogni tweak deve avere una motivazione tecnica plausibile.

Quando il beneficio è incerto, dichiararlo.

Per ogni tweak indicare:

* cosa modifica;
* perché esiste;
* quando può essere utile;
* effetti collaterali;
* come ripristinarlo.
